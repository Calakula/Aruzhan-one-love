js/main.js

Этот файл есть на каждой странице. Он делает пять вещей: переключает тему (тёмная/светлая) и запоминает выбор, открывает/закрывает мобильное меню, даёт глобальное модальное окно window.BorahaeModal, плавно скроллит к якорям и показывает кнопку «Наверх». Модальным окном пользуются страницы Members, Discography и Timeline — поэтому main.js всегда подключён раньше страничного скрипта.Бұл файл әр бетте бар. Ол бес іс атқарады: тақырыпты (қараңғы/жарық) ауыстырып, таңдауды есте сақтайды, мобильді мәзірді ашады/жабады, ғаламдық модальді терезе window.BorahaeModal береді, якорьларға тегіс скролл жасайды және «Жоғары» батырмасын көрсетеді. Модальді терезені Members, Discography және Timeline беттері қолданады — сондықтан main.js бет скриптінен бұрын қосылады.This file is on every page. It does five things: switches the theme (dark/light) and remembers it, opens/closes the mobile menu, provides the global modal window.BorahaeModal, smooth-scrolls to anchors and shows a “Back to top” button. The Members, Discography and Timeline pages use the modal, so main.js is always loaded before the page script.

Ссылки вида href="#id" прокручивают страницу плавно, а быстрые повторные клики не ломают анимацию.href="#id" түріндегі сілтемелер бетті тегіс айналдырады, ал жылдам қайталанған басулар анимацияны бұзбайды.Links like href="#id" scroll smoothly, and fast repeated clicks do not break the animation.

67    var busy = false;68    function scrollToY(y) {69      if (busy) return; busy = true;70      window.scrollTo({ top: y, behavior: 'smooth' });71      setTimeout(function () { busy = false; }, 600);72    }

Так выполняется требование брифа: «быстрые повторные клики не ломают эффект».busy — құлып-жалауша. scrollToY(y): құлып жабық болса — шығамыз; әйтпесе жауып, behavior: 'smooth' бар scrollTo іске қосамыз да, 600 мс-тан кейін (setTimeout) құлыпты ашамыз. Брифтің «жылдам қайталанған басулар эффектіні бұзбауы керек» талабы осылай орындалады.busy is a lock flag. scrollToY(y): if locked — return; otherwise lock, start scrollTo with behavior: 'smooth' and unlock after 600 ms (setTimeout). Әйтпесе preventDefault() күрт секіруді тоқтатады, ал біз элемент орнына өзіміз айналдырамыз: getBoundingClientRect().top + scrollY - 90 (90 px — бекітілген шапка үшін қор).Take every link whose href starts with # (selector a[href^="#"]). Зачем весь код обёрнут в IIFE?Неге бүкіл код IIFE ішінде?Why is all the code wrapped in an IIFE?
Чтобы переменные (modal, saved, busy) были приватными и не конфликтовали с переменными других файлов. Наружу выставлено только то, что нужно: window.BorahaeModal.
Айнымалылар (modal, saved, busy) жеке болып, басқа файлдардың айнымалыларымен қақтығыспауы үшін. Сыртқа тек қажеттісі шығарылған: window.BorahaeModal.
So variables (modal, saved, busy) stay private and do not clash with other files. Only what is needed is exposed: window.BorahaeModal.
Что будет, если подключить members.js раньше main.js?members.js-ті main.js-тен бұрын қосса не болады?What happens if members.js is loaded before main.js?
При клике на карточку window.BorahaeModal ещё не существует (undefined) — будет ошибка «Cannot read properties of undefined». Поэтому в HTML порядок: main.js, потом страничный скрипт.
Карточканы басқанда window.BorahaeModal әлі жоқ (undefined) — «Cannot read properties of undefined» қатесі шығады. Сондықтан HTML-де реті: main.js, содан кейін бет скрипті.
On a card click window.BorahaeModal does not exist yet (undefined) — you get “Cannot read properties of undefined”. That is why the HTML order is main.js, then the page script.
Что такое localStorage и зачем try/catch?localStorage дегеніміз не және try/catch неге керек?What is localStorage and why try/catch?
Хранилище «ключ → строка» в браузере, данные остаются после закрытия вкладки. В приватном режиме или при запрете cookie доступ может бросить исключение — try/catch не даёт сайту сломаться.
Браузердегі «кілт → жол» сақтауы, қойынды жабылса да деректер қалады. Жеке режимде немесе cookie тыйым салынғанда қолжетімділік ерекшелік тастауы мүмкін — try/catch сайтты бұзбайды.
A “key → string” store in the browser; data survives closing the tab. In private mode or with storage blocked, access can throw — try/catch keeps the site working.
Почему textContent, а не innerHTML?Неге innerHTML емес, textContent?Why textContent instead of innerHTML?
textContent вставляет строку как текст, поэтому даже если в ней есть <script>, он не выполнится. innerHTML разбирает HTML — это риск XSS.
textContent жолды мәтін ретінде қояды, сондықтан ішінде <script> болса да орындалмайды. innerHTML HTML-ді талдайды — бұл XSS қаупі.
textContent inserts the string as text, so even a <script> inside will not run. innerHTML parses HTML — an XSS risk.
Чем e.target отличается от элемента, на который повешен обработчик?e.target өңдеуші ілінген элементтен несімен ерекшеленеді?How does e.target differ from the element the handler is attached to?
Обработчик висит на modal, но событие всплывает от самого глубокого элемента. e.target — тот, по кому кликнули. Сравнив с modal, мы отличаем клик по фону от клика внутри окна.
Өңдеуші modal-да тұр, бірақ оқиға ең терең элементтен жоғары қарай «көтеріледі». e.target — басылған элемент. modal-мен салыстырып, фонды басуды терезе ішіндегі басудан ажыратамыз.
The handler is on modal, but events bubble up from the deepest element. e.target is the one clicked. Comparing it with modal separates a backdrop click from a click inside the box.
